# 리포트 조치 링크 ("해지하러 가기") 설계

2026-10-19

## 왜

지금 리포트는 "넷플릭스 구독 중, 해지를 고려해 보세요"까지만 말한다. 사용자는 리포트를 닫고
넷플릭스에 들어가 해지 메뉴를 직접 찾아야 한다. 리포트에서 버튼 하나로 **그 조치를 하는 페이지**
(홈페이지가 아니라 해지·탈퇴·보안 설정 페이지)로 바로 데려다준다.

IDly-PoC의 에이전트는 서버/확장 브라우저가 화면을 대신 클릭하는 방식이었다. 이번에는 그걸 가져오지
않는다. 1차 목표는 **링크로 데려다주는 데까지**다. PoC에서 가져오는 것은 두 가지뿐이다:
"검증된 것만 쓴다"는 원칙(flows.py의 `verified`)과, 모를 때 구글 검색으로 넘기는 대체 경로(Progress.tsx).

## 목표

- 결제 후 전체 리포트의 아래 세 곳에 조치 버튼을 단다.
  - **구독** 섹션의 각 구독 → "해지하러 가기"
  - **안 쓰는 계정** 섹션의 각 계정 → "탈퇴하러 가기" (구독 해지를 권한 계정은 "해지하러 가기")
  - **확인할 일** 섹션의 각 `보안` 항목 → "보안 설정 열기" (비밀번호 변경·로그인 활동·기기 관리 페이지)
- 리포트를 요청하면 위 항목 **모두에 버튼이 반드시 하나 붙는다.** 링크를 못 찾았다고 버튼이 빠지지 않는다.
- 웹 화면과 PDF 둘 다에서 링크가 눌린다.

## 하지 않는 것

- 화면 자동 조작(PoC 에이전트, 크롬 확장, 서버 브라우저). 링크 이동까지만.
- 결제 전(잠긴) 미리보기에는 버튼을 넣지 않는다. 잠긴 목록은 서비스 이름도 가리므로 넣을 자리가 없다.
- 해지 완료 여부 추적, "해지했어요" 체크 같은 상태 관리.

## 실패로 보는 것 (기술적으로 동작해도)

- **IDly가 사용자를 피싱·광고 블로그·엉뚱한 사이트로 보내는 것.** 보안 서비스라서 가장 나쁜 결과다.
  그래서 검색으로 찾은 링크는 도메인 검증을 통과해야만 쓴다(아래).
- 링크를 찾느라 리포트 완성이 눈에 띄게 늦어지거나, 검색 API 장애로 리포트가 실패하는 것.
- 버튼이 홈페이지로만 가서 "바로 데려다준다"는 약속을 못 지키는 것 — 큐레이션 목록은 조치 페이지 주소여야 한다.

## 링크를 고르는 순서

계정 하나, 조치 하나(`해지` | `탈퇴` | `보안`)마다:

1. **큐레이션 목록** — 사람이 공식 도움말·실제 페이지로 확인해 코드에 넣어 둔 링크.
2. **검색 캐시(DB)** — 예전에 3번으로 찾아 검증을 통과한 링크. 90일이 지나면 다시 찾는다.
3. **웹 검색 API** — 1·2에 없을 때 리포트를 만드는 중에 찾는다. 검증을 통과하면 결과를 2에 저장한다.
4. **구글 검색 링크** — 위가 모두 실패하거나 검증에서 떨어지면
   `https://www.google.com/search?q=<서비스명> <조치> 방법`. 이 단계는 실패하지 않으므로 버튼이 항상 붙는다.

버튼 문구는 출처에 따라 다르게 한다: 1~3은 "해지하러 가기", 4는 "해지 방법 찾아보기".
사용자가 구글 검색 결과로 가면서 해지 페이지로 간다고 착각하지 않게 하기 위해서다.

## 큐레이션 목록

- 새 모듈 `action_links.py`에 `도메인 → {조치: URL}` 표로 둔다. 키는 analysis.py 계정의 `id`
  (= 기준 도메인, 예: `netflix.com`)와 같다.
- 대상은 analysis.py `KNOWN_SERVICES`의 130개 서비스. 각 서비스의 해지·탈퇴·보안 링크를 공식 도움말 또는
  실제 페이지 주소로 확인해 채운다. **확인하지 못한 칸은 비워 둔다** — 추측으로 채우지 않는다.
- "확인됨"의 기준 (빌더 체크 반영, 내 판단): 서비스의 공식 도움말·공식 페이지에 그 URL(또는 그 URL로 가는
  메뉴 경로)이 적혀 있는 것을 웹에서 직접 본 경우. 로그인해야 열리는 해지 페이지는 공식 도움말에 적힌
  주소면 인정한다. 칸마다 확인한 출처 URL을 주석으로 남겨 PR에서 검수할 수 있게 한다.
  빈 칸은 2~4단계가 맡는다.
- 해지 전용 페이지가 없는 서비스(예: 앱스토어 결제)는 그 서비스의 구독 관리 페이지나 공식 해지 안내
  페이지로 연결한다.
- 특수 계정:
  - Apple 앱스토어 구독(`id`가 `apps.apple.com/…`)의 해지 → `https://apps.apple.com/account/subscriptions`
  - Google 계정 보안 알림 → `https://myaccount.google.com/security` (analysis.py 안내 문구에 이미 나오는
    `device-activity`·`apppasswords`·`notifications`와 일관되게)
- 서비스의 링크가 기준 도메인 밖에 있는 경우(예: YouTube Premium 해지가 `youtube.com/paid_memberships`,
  Google 계정은 `google.com`)를 위해 서비스별 **허용 도메인** 목록도 함께 둔다. 이 목록은 4단계 검증에도 쓴다.

## 웹 검색 API

- 리포트에 이미 있는 `OPENAI_API_KEY`로 OpenAI의 웹 검색 도구(Responses API `web_search`)를 쓴다.
  키가 없으면 3단계를 건너뛴다(로컬 개발).
- 질의에는 **서비스 이름·도메인·조치만** 보낸다. 사용자 메일 주소나 메일 내용은 보내지 않는다.
- 응답에서 URL 하나를 받아 검증한다:
  - `https`만
  - 호스트가 그 계정의 도메인이거나 그 하위 도메인, 또는 큐레이션 목록의 허용 도메인
  - 사용자 정보(`user:pass@`), 포트 지정, IP 주소 호스트는 거절
  - 검증에 떨어지면 버리고 4단계로
- 링크가 실제로 열리는지 서버에서 가져와 확인하지는 않는다. 호스트 검증으로 충분하고, 서버가 외부 URL을
  가져오는 경로를 새로 만들지 않기 위해서다.
- **결제한 리포트에서만 돈다** (사용자 결정). 결제 전에는 1·2·4단계만으로 링크를 정한다.
  결제 전 화면에는 버튼이 안 보이므로, 결제하지 않을 리포트에 검색 비용을 쓰지 않기 위해서다.
- 비용·시간 상한: 리포트 하나당 검색 최대 20건, 동시 5건, 건당 10초, 전체 20초. 넘친 항목은 4단계.
  (빌더 체크 반영: 진행 화면이 링크 단계 동안 "완료" 전에 머무르므로 60초 → 20초로 줄임. 내 판단)

## 검색 캐시

- DB에 표 `action_links(domain, action, url, source, found_at)`를 추가한다(SQLite·Postgres 둘 다,
  db.py의 기존 `CREATE TABLE IF NOT EXISTS` 방식). 기본키는 `(domain, action)`.
- 검증을 통과한 검색 결과만 저장한다. 구글 검색 대체 링크는 저장하지 않는다(다음 리포트에서 다시 찾아보게).
- 사용자 데이터가 아니므로 회원 탈퇴 시 지울 대상이 아니다.
- 캐시에 들어간 링크 목록은 나중에 사람이 확인해 큐레이션 목록으로 옮기는 재료가 된다.

## 리포트 데이터와 화면

- 링크는 **정해서 리포트 데이터에 저장**하고, 화면·PDF는 저장된 값만 쓴다. 볼 때마다 결과가 바뀌거나
  검색이 돌지 않게 하기 위해서다. 저장 형태:
  - 계정: `"actions": {"해지": {...}, "탈퇴": {...}, "보안": {...}}` — 그 계정에 필요한 조치만
  - 보안 insight: 항목별로 `"action": {...}` (아래 "보안 항목")
  - 각 값은 `{"url": "...", "source": "curated|cache|search|fallback"}`
- 링크가 정해지는 두 시점:
  1. **분석 완료** — app.py `start_report`의 `on_done`에서 `report.save()` 전에 1·2·4단계로 정한다.
     네트워크 호출이 없으므로 진행 화면이 늦어지지 않는다. 이미 결제된 메일함(`report.paid`가 처음부터 참)이면
     여기서 바로 2번도 이어서 한다.
  2. **결제 확인** — 리포트가 결제됨으로 바뀌는 곳(Paddle 웹훅 `paid`, `PAYMENT_MODE=mock` 결제,
     개발용 `dev-confirm`)에서 백그라운드 스레드로 `fallback` 칸만 3단계로 다시 찾는다. 찾으면 리포트 데이터를
     고쳐 저장하고, 미리 만든 PDF를 버리고 다시 만든다. 웹훅 응답은 기다리지 않는다(결제사 재전송 방지).
     같은 리포트에 두 번 돌지 않게 한다. 환불은 링크를 되돌리지 않는다.
  - 결제 직후 몇 초 동안은 구글 검색 대체 링크가 보일 수 있다. 감수한다.
- 링크 단계에서 무슨 일이 나도(예외·타임아웃) 리포트는 그 시점 링크로 완성·유지된다.
- 예전에 저장된 리포트(`actions`가 없음)는 그릴 때 1단계와 4단계만으로 채운다. 검색은 돌리지 않는다.
- **안 쓰는 계정** (빌더 체크 반영, 내 판단): 모든 행에 버튼을 단다. analysis.py가 `recommended == "구독 해지"`로
  본 계정은 해지 링크("해지하러 가기"), 나머지는 탈퇴 링크("탈퇴하러 가기"). 기존 "탈퇴는 이럴 때만 권해요"
  안내 문구는 그대로 둔다 — 버튼은 권유가 아니라 선택지다.
- **보안 항목** (빌더 체크 반영, 내 판단): 확인할 일의 `보안` insight마다 버튼 하나. Google 계정 알림처럼
  항목마다 맞는 페이지가 따로 있으면 그 페이지(`device-activity`, `apppasswords`, `notifications`),
  그 밖에는 그 서비스의 `보안` 링크. 그래서 보안 링크는 insight 단위로 저장한다.
- 렌더링(report_view.py):
  - `_subscriptions`, `_unused`, `_todo`(`보안` 항목만)의 각 행에 버튼 하나
  - `<a href="…" target="_blank" rel="noopener noreferrer">`, URL은 기존 `_e`로 이스케이프
  - PDF는 크로미움 인쇄라 `<a>`가 그대로 눌리는 링크로 남는다
- 샘플 리포트(`sample_report.json`)에도 `actions`를 넣어 샘플에서도 버튼이 보이게 한다.

## 테스트

- 고르는 순서: 큐레이션 > 캐시 > 검색 > 대체, 캐시 만료
- 검증: 다른 도메인·http·IP·포트·`user@` URL 거절, 하위 도메인·허용 도메인 통과
- 검색 API 실패·타임아웃·키 없음 → 대체 링크, 리포트는 정상 완성
- 결제 전에는 검색이 돌지 않음 / 결제 확인(웹훅·mock·dev-confirm) 뒤 `fallback` 칸만 검색, PDF 재생성,
  두 번 돌지 않음 / 처음부터 결제된 메일함은 분석 완료 때 검색
- 상한(20건) 초과 항목은 대체 링크
- 렌더링: 세 섹션에 버튼이 있고, 잠긴 미리보기에는 없음, 대체 링크 문구가 다름, URL 이스케이프
- 기존 리포트(`actions` 없음)도 버튼이 나옴
- 검색 질의에 사용자 메일 주소가 들어가지 않음

## 빌더에게 맡기는 것

- 버튼 모양·위치(행 오른쪽 vs 아래)는 report.css의 기존 스타일에 맞춰 정한다.
- 조치 이름의 사용자 노출 문구 다듬기.
- 큐레이션 130개를 채우는 작업 방식(병렬 조사 등). 단, 확인되지 않은 링크는 넣지 않는다.

## 범위

IDly-report에만 넣는다. IDly-2.0-Server로 옮기는 것은 이번 범위가 아니다.

## 배포 메모

- 새 환경변수는 없다(`OPENAI_API_KEY` 재사용). 검색 상한을 바꾸고 싶으면 상수로 둔다.
- 작업 브랜치 `feat/action-links`(main 기준), 완료 후 PR.
